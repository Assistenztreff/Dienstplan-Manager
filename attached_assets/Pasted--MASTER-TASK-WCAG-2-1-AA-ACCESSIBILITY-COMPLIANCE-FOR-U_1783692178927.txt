### MASTER TASK: WCAG 2.1 (AA) ACCESSIBILITY COMPLIANCE FOR USER-FRONTEND

We need to update the user-facing Frontend of the Dienstplan App to strictly comply with WCAG 2.1 (AA) standards to achieve a Google Lighthouse Accessibility score of 90+. 
Focus ONLY on the user-frontend (Shift View, Calendar Grid, Multi-Select elements). Ignore the Operator/Admin Dashboard for now.

Please execute this implementation in the following structured Tasks sequentially. Do NOT skip any tasks.

---

### TASK 1: SEMANTIC HTML & ARIA ROLES (USER FRONTEND)
1. Open the primary user-facing views (e.g., the Calendar sheet and the Shift List/Table view).
2. Refactor any generic layout containers (like <div> or <span>) that act as interactive elements into semantic HTML5 components (<button>, <main>, <nav>, <section>).
3. For complex custom components (like the custom Multi-Select toggle and Month Switcher):
   - Add explicit ARIA attributes (e.g., `aria-expanded`, `aria-label`, `aria-controls`).
   - Ensure the Month Switcher indicates the current active month to screen readers using `aria-live="polite"`.
4. Run a local typecheck to ensure code compiling remains 100% green.

---

### TASK 2: KEYBOARD NAVIGATION & FOCUS MANAGEMENT
1. Ensure every interactive element in the Shift Table, Calendar Grid, and the compact sticky header is fully focusable via the [TAB] key.
2. Implement a visible, high-contrast `:focus-visible` ring on all interactive elements (buttons, selectors, inputs) using Tailwind CSS classes (e.g., `focus-visible:ring-2 focus-visible:ring-blue-600 focus-visible:outline-none`).
3. For the Multi-Select shift tool, ensure selection can be toggled using the [SPACE] or [ENTER] keys when focused.

---

### TASK 3: COLOR CONTRAST & VISUAL ACCESSIBILITY
1. Verify and adjust the color palette for all shift status badges, assistant initials, and text tags.
2. Text-to-background contrast ratios MUST strictly meet WCAG AA requirements:
   - Minimum 4.5:1 for normal text.
   - Minimum 3:1 for large text.
3. Ensure that information (e.g., specific shift types or conflicts) is never conveyed *only* by color. Add text descriptors or visible icons alongside background badges.

---

### TASK 4: AUTOMATED ACCESSIBILITY AUDIT & VALIDATION
1. Write a lightweight automated end-to-end check or utility script to audit the DOM structure for missing `alt` tags, broken button labels, or missing roles.
2. Ensure `pnpm run typecheck` passes without errors.
3. Provide a summary of the changes made to the components and report back once the User-Frontend is fully accessible.
